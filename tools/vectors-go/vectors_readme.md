# Vectors

Generated by `tools/vectors-go` (this file included; its source is `tools/vectors-go/vectors_readme.md`). That tool is the reference for canonical bytes and is **not** the code under test. Do not edit anything here by hand. Do not regenerate in a PR that also changes code. Regenerate with `make vectors`.

Required set: SPEC §11. Seeds: `spec/test-seed.txt` (published, not secret).

## Layout

One directory per vector:

- `positive/<name>/` — a log a verifier must accept with exit 0.
- `negative/<name>/` — a log a verifier must reject with exit 2.

Each vector directory holds:

- one or more log files named `test.<first_seq:016d>.jsonl` (SPEC §3.6), in seq order by name. Every log starts at seq 0.
- `keyring.json` only when the vector needs its own keyring (rotation vectors). Otherwise use `../../keyring.json`.
- exactly one sidecar:
  - `vector.hash` (positive) — one `sha256:<hex>` per record, in log order across files.
  - `vector.expect` (negative) — `check=<N> exit=2`, where N is the **first** check in SPEC §5 order that fails. Some negatives would also fail later checks.
- the `anchor` vector also holds `submission.json` (anchor domain, signed by `gate-test-1`) and `anchors/test/<seq:016d>.json`, the sink receipt (anchor-receipt domain, signed by `sink-test-1`), laid out as the sink's object keys (SPEC §3.7).

At the top level: `keyring.json` (gate-test-1 for all seqs, sink-test-1) and this file. The reasons file is `spec/reasons.txt`.

## Byte rules

- Every `.jsonl` and `.json` file is canonical lines, each followed by `\n`. Negative vectors break this on purpose.
- A record's hash is `sha256` of the line **without** its `\n`, and includes `sig` (SPEC §3.2).
- Signatures are over `DOMAIN || JCS(object without its "sig" member)`. This applies to records, anchor submissions, and sink receipts alike.
- A sink receipt's `sink` field is the sink's `kid` in the keyring.
- Every value is fixed in the generator's source. Two runs produce identical bytes.

## Manifest

`../vectors.sha256` lists every file here. CI runs `cd spec && sha256sum -c vectors.sha256`.
